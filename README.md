# Seller Lead Sniper

Сервис мониторинга Telegram-сообществ продавцов маркетплейсов **Wildberries** и **Ozon**.
Он в реальном времени перехватывает сообщения, в которых селлеры жалуются на потерю
маржи, штрафы, принудительные автоакции и логистические кассовые разрывы, оценивает
серьёзность проблемы и доставляет готовый лид в закрытый канал **MarginGuard**.

Проект рассчитан на работу в режиме 24/7 на Linux-сервере под управлением systemd.

## Ключевые возможности

- **MTProto-слушатель на Telethon.** Подключение к Telegram по API ID/Hash, приём
  сообщений из выбранных чатов и работа через HTTP/SOCKS-прокси.
- **Двухуровневая фильтрация.**
  1. Локальные гейты в [`filters.py`](filters.py): длина сообщения, стоп-слова
     (реклама агентств, накрутка, «пишите в личку») и триггерные стемы
     («автоакци», «штраф», «в минус», «кассовый разрыв» и т.д.).
  2. Семантический скоринг через LLM в [`classifier.py`](classifier.py):
     модель определяет, является ли сообщение реальной болью селлера, присваивает
     категорию, краткое резюме и уверенность по **10-балльной шкале**.
- **Автоматический скаутинг чатов** в [`auto_discover.py`](auto_discover.py):
  поиск по ключевым словам, пре-джойн аудит активности (свежесть сообщений,
  количество авторов, проверка участников через `GetFullChannelRequest`) и
  безопасное вступление с защитой от антифлуда.
- **Дедупликация и аудит в SQLite** в [`db.py`](db.py): режим WAL, таблица
  `seen_messages` для отсечения репостов и таблица `discovered_chats` для
  истории скаутинга.
- **Безопасная маршрутизация алертов** в [`notifier.py`](notifier.py): отправка
  через Telegram Bot API в приватные каналы с карточкой контакта, категорией,
  рейтингом и цитатой проблемы.
- **Отказоустойчивость.** Падение LLM-провайдера, таймаут Telegram или
  неверный токен не роняют пайплайн: каждый этап возвращает предсказуемый
  статус и пишет структурированный лог.

## Как это работает

Пайплайн собран в [`pipeline.py`](pipeline.py) и вызывается из
[`main.py`](main.py) в режимах `--demo` и `--live`:

1. **Локальный фильтр** — отсекает шум до платных запросов к LLM.
2. **Дедупликация** — проверяет нормализованный хеш сообщения в SQLite.
3. **LLM-классификатор** — решает, является ли автор селлером с реальной
   проблемой, и возвращает JSON:
   ```json
   {
     "is_lead": true,
     "category": "Слив маржи / Убыток",
     "summary": "Маржа упала до 3% из-за автоакции",
     "confidence": 9
   }
   ```
4. **Доставка алерта** — формирует HTML-сообщение и отправляет его в
   соответствующий канал через Bot API.

Поддерживаемые категории:

- `Автоакция / Цены`
- `Логистика / Хранение`
- `Штрафы / Удержания`
- `Слив маржи / Убыток`
- `Другое`

## Установка и локальный запуск

### Требования

- Python **3.12+**
- Аккаунт Telegram с доступом к API (создайте приложение на
  [my.telegram.org/apps](https://my.telegram.org/apps))
- Бот Telegram, созданный через [@BotFather](https://t.me/BotFather), с правами
  администратора в целевом канале
- Ключ OpenAI-совместимого LLM-провайдера (DeepSeek, OpenRouter и т.п.)

### Клонирование и виртуальное окружение

```bash
git clone https://github.com/feodorkuclyonckov-afk/lead-sniper.git seller-lead-sniper
cd seller-lead-sniper

python -m venv .venv
# Linux / macOS
source .venv/bin/activate
# Windows (PowerShell)
# .venv\Scripts\Activate.ps1

pip install --upgrade pip
pip install -r requirements.txt
```

### Настройка `.env`

Скопируйте шаблон и заполните значения:

```bash
cp .env.example .env
```

Минимально необходимые переменные:

| Переменная | Описание |
| --- | --- |
| `TG_API_ID` | `api_id` приложения Telegram (целое число). |
| `TG_API_HASH` | `api_hash` приложения Telegram (32-символьный hex). |
| `TG_SESSION_NAME` | Имя файла сессии Telethon (по умолчанию `session_auth_test`). |
| `TG_PHONE` | Телефон в формате E.164 для авторизации (можно не заполнять). |
| `TG_MONITOR_CHATS` | Список чатов через запятую для `--live`. |
| `LLM_API_KEY` | Ключ LLM-провайдера. Пустое значение отключает LLM-этап. |
| `LLM_BASE_URL` | Базовый URL OpenAI-совместимого API (по умолчанию `https://api.deepseek.com`). |
| `LLM_MODEL` | Модель (по умолчанию `deepseek-chat`). |
| `TELEGRAM_BOT_TOKEN` | Токен бота для отправки алертов. |
| `TELEGRAM_ALERT_CHAT_ID` | ID канала или `@username` для алертов по умолчанию. |

Опциональные переменные:

| Переменная | Описание |
| --- | --- |
| `PROXY_TYPE` | `http`, `socks5` или `socks4` (по умолчанию `http`). |
| `PROXY_HOST`, `PROXY_PORT` | Адрес и порт прокси. Пустой `PROXY_HOST` — прямое подключение. |
| `PROXY_USER`, `PROXY_PASS` | Логин и пароль прокси (если требуются). |
| `ALERT_CHAT_PRICING` | Отдельный канал для категории «Автоакция / Цены». |
| `ALERT_CHAT_LOGISTICS` | Отдельный канал для категории «Логистика / Хранение». |
| `ALERT_CHAT_PENALTIES` | Отдельный канал для категории «Штрафы / Удержания». |
| `ALERT_CHAT_MARGIN` | Отдельный канал для категории «Слив маржи / Убыток». |
| `ALERT_CHAT_DEFAULT` | Резервный канал, если `TELEGRAM_ALERT_CHAT_ID` не задан. |
| `DISCOVERY_MIN_MEMBERS` | Минимум участников для кандидата (по умолчанию `50`). |
| `DISCOVERY_DAILY_JOIN_LIMIT` | Лимит вступлений в сутки (по умолчанию `5`). |
| `DISCOVERY_MAX_AGE_HOURS` | Максимальный возраст последнего сообщения в часах (по умолчанию `48`). |
| `DISCOVERY_MIN_MESSAGES_7D` | Минимум сообщений за 7 дней (по умолчанию `5`). |
| `DISCOVERY_HISTORY_LIMIT` | Сколько последних сообщений анализировать (по умолчанию `10`). |

> **Важно:** `.env` содержит секреты и никогда не должен попадать в git.
> В репозитории хранится только `.env.example`.

## Авторизация в Telegram

Первый запуск требует интерактивной авторизации. Сессия сохраняется в
`<TG_SESSION_NAME>.session` и переиспользуется всеми модулями.

### Вход по коду

```bash
python auth_test.py
```

Скрипт запросит телефон (или возьмёт `TG_PHONE`), отправит код в Telegram и
попросит ввести его. Если включена двухфакторная аутентификация, пароль будет
запрошен скрытым вводом.

### Вход по QR-коду

```bash
python auth_test.py --qr
```

В корне проекта появится `qr.png`. Отсканируйте его в Telegram:
**Настройки → Устройства → Подключить устройство**. Токен живёт около 30 секунд,
скрипт автоматически обновляет QR-код. После успешного входа `qr.png` удаляется.

### Неинтерактивный сценарий (CI/агент)

```bash
python auth_test.py --request-code
python auth_test.py --code 12345
# при включённой 2FA:
python auth_test.py --code 12345 --password '<cloud-password>'
```

Для сброса повреждённой сессии используйте `--fresh`: старый файл будет
переименован в `<TG_SESSION_NAME>.session.stale.bak`.

## Демо-режим и тесты

### Демо без сети

```bash
python main.py --demo
```

В пайплайн подаются реалистичные сообщения селлеров. Первые четыре проходят
фильтр и классификацию, два шумовых отсекаются локально. Если в `.env` заданы
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_ALERT_CHAT_ID`, алерты будут реально отправлены
в Telegram.

Полезные флаги:

```bash
python main.py --demo --delay 0.5 --log-level DEBUG
```

### Тесты

```bash
pytest -q
```

Либо автономные скрипты (не требуют pytest):

```bash
python test_filters.py
python test_classifier.py
python test_notifier.py
python test_pipeline.py
python test_discovery.py
python test_join_chats.py
python test_auth_test.py
```

Тесты не обращаются к реальным Telegram/LLM API: внешние сервисы замоканы.

## Эксплуатация на сервере

### Запуск в live-режиме

```bash
python main.py --live
```

Список чатов берётся из `TG_MONITOR_CHATS` или из флага `--chats`:

```bash
python main.py --live --chats @wb_chat_sellers,@ozon_sellers
```

Если список пуст, слушатель принимает сообщения из всех чатов, куда доставляет
Telegram. Для остановки нажмите `Ctrl+C` — клиент завершится корректно.

### Systemd-демон

Unit-файл [`seller-lead-sniper.service`](seller-lead-sniper.service) рассчитан на
размещение проекта в `/opt/seller-lead-sniper`:

```bash
sudo cp seller-lead-sniper.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now seller-lead-sniper
sudo systemctl status seller-lead-sniper
```

Просмотр логов:

```bash
sudo journalctl -u seller-lead-sniper -f
```

Перезапуск после обновления кода:

```bash
sudo systemctl restart seller-lead-sniper
```

## Автоматический скаутинг чатов

[`auto_discover.py`](auto_discover.py) ищет публичные чаты по ключевым словам из
[`keywords.txt`](keywords.txt), проверяет активность **до** вступления и ведёт
аудит в SQLite.

### Безопасная проверка без вступления

```bash
python auto_discover.py --dry-run
```

Скрипт покажет заголовок, число участников, дату последнего сообщения и причину
прохождения/отказа, но не будет вступать в чаты.

### Вступление с лимитом

```bash
python auto_discover.py --limit 2
```

`--limit` ограничивает число вступлений за запуск; дополнительно действует
суточный лимит `DISCOVERY_DAILY_JOIN_LIMIT`.

### Свои ключевые слова

```bash
python auto_discover.py --keyword "wildberries чат" --keyword "ozon селлеры" --dry-run
```

### Ручное вступление в курируемый список

```bash
python join_chats.py --dry-run
python join_chats.py --limit 5
```

`join_chats.py` умеет искать чаты по ключевым словам:

```bash
python join_chats.py --discover --limit 3
```

Успешно разрешённые чаты автоматически дописываются в `TG_MONITOR_CHATS` в
`.env`, не удаляя уже отслеживаемые.

## Безопасность и лимиты

- **Изоляция сессий.** Файлы `*.session*` содержат ключи авторизации и
  приравниваются к паролям. Они исключены из git и не должны передаваться
  третьим лицам.
- **Секреты не коммитятся.** `.env`, `.env.*`, `*.session*`, `*.db*`, `qr.png`,
  `*.log`, `.auth_pending.json` и локальные операционные скрипты перечислены в
  [`.gitignore`](.gitignore). В репозитории остаётся только `.env.example`.
- **2FA.** Пароль облачной двухфакторной аутентификации никогда не сохраняется
  на диск: он запрашивается скрытым вводом или передаётся флагом `--password`.
- **QR-токен.** `qr.png` — краткоживущий credential. После успешного входа файл
  удаляется, а в `.gitignore` он исключён.
- **Антифлуд при скаутинге.**
  - 10–25 секунд случайного джиттера между поисковыми запросами;
  - 180–360 секунд между `JoinChannelRequest`;
  - суточный лимит вступлений (`DISCOVERY_DAILY_JOIN_LIMIT`, по умолчанию 5);
  - обработка `FloodWaitError` с логированием и остановкой;
  - `ChannelsTooMuchError` останавливает запуск и сообщает лимит аккаунта.
- **Пре-джойн аудит.** Кандидат отбрасывается, если он деактивирован, не имеет
  публичного username, уже покинут/недоступен, слишком мал, заброшен или
  накручен одним ботом.
- **Прокси.** Поддерживаются HTTP, SOCKS5 и SOCKS4. Для продакшена
  рекомендуется выделенный прокси, чтобы не светить домашний IP аккаунта.

## Ограничения

- Для `--live` и скаутинга нужен авторизованный аккаунт Telegram; бот не может
  читать историю чатов от своего имени.
- Бот должен быть добавлен администратором в целевой канал, иначе Bot API
  вернёт ошибку доставки.
- Без `LLM_API_KEY` семантический этап отключается: сообщения, прошедшие
  локальный фильтр, не будут классифицированы (статус `llm_unavailable`).
- `--demo` не требует сети, но для реальной отправки алертов нужны
  `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ALERT_CHAT_ID`.
- Проект не является юридическим консультантом и не заменяет ручную проверку
  лида перед продажей.
